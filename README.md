# Creative Desk — мини-сервис управления креативным отделом

Веб-сервис для постановки задач, отслеживания и контроля их выполнения между медиабайерами и креативщиками.
Включает Kanban-доску, автоматический учёт времени, учёт расходов AI-кредитов и аналитику для руководителя.

**Демо:** `<ссылка после деплоя>` · пароль у всех тестовых пользователей — `demo123` (на странице входа есть кнопки быстрого входа).

| Роль | Email | Что может |
|---|---|---|
| Руководитель | `lead@demo.ru` | всё видит, назначает и переназначает исполнителей, принимает работу и возвращает на правки, редактирует и удаляет задачи, аналитика |
| Байер | `buyer1@demo.ru`, `buyer2@demo.ru`, `buyer3@demo.ru` | создаёт ТЗ, редактирует свои задачи, принимает работу или отправляет на правки |
| Креативщик | `creative1@demo.ru` … `creative4@demo.ru` | сам берёт задачи, сдаёт результат (файлы и ссылки), указывает AI-расходы, отказывается от задачи |

## Возможности

- **ТЗ через форму:** оффер, GEO, тип креатива, количество, описание, референсы (ссылки и файлы), приоритет, дедлайн с быстрыми пресетами.
- **Kanban:** Новые → В работе → На проверке → Правки → Готово. Карточки можно перетаскивать между колонками, а сервер проверяет, допустим ли переход для этой роли. Если для действия нужен ввод (сдача работы, правки, назначение), открывается нужная форма. Есть фильтры по исполнителю, байеру, приоритету и типу, поиск, «Только мои». Доска обновляется сама каждые 20 секунд.
- **Работа с задачей:** креативщик берёт задачу, прикрепляет результат (файлы и ссылки, каждая сдача — отдельный раунд), байер принимает работу или отправляет на правки с обязательным комментарием. Есть комментарии.
- **Правки наглядны:** задача остаётся в колонке «Правки» до повторной сдачи. Кнопка «Начать правки» не меняет статус, а только фиксирует начало доработки. На карточке видно, ждёт ли задача креативщика или доработка уже идёт.
- **Учёт времени:** система сама фиксирует `created_at`, `taken_at`, `first_submitted_at` (первая сдача), `submitted_at` (последняя сдача) и `completed_at`. Время «Правок» делится на ожидание и доработку. По журналу переходов считается время в каждом статусе: ожидание взятия, работа, проверка, правки. Отдельно считаются общее время (lead time) и время от взятия до приёмки (cycle time).
- **AI-расходы:** сервис и кредиты (несколько строк за раз) указываются при сдаче или в любой момент. Каждая запись привязана к раунду: 0 — основная работа, 1..N — правки.
- **Аналитика руководителя** (за период): количество задач и разбивка по статусам, загрузка каждого креативщика (в работе, на проверке, на правках, единицы креативов), среднее время выполнения, взятия и цикла, просрочки (текущие и сданные с опозданием, плюс список), доля сданных в срок, доля задач с правками, AI-кредиты по сервисам (основная работа и правки), матрица «сервис × исполнитель», динамика по дням, разрезы по типам креативов и байерам.
- **История действий:** журнал без удаления записей. В нём все события: создание, каждая смена статуса (из какого в какой), изменения полей с прежними и новыми значениями, назначения, расходы, референсы, удаление. Журнал виден в карточке задачи и общей лентой с фильтром.
- Светлая и тёмная тема (по системной настройке), адаптивная вёрстка под мобильные.

## Версия 2 (в разработке, ветка `feature/v2`)

Цель — замкнуть цикл «ТЗ → креатив → приёмка → тест → результаты → вердикт → вариации победителя». Полная спецификация — в `creative-desk-features-spec.md`. Готовы фазы 1–4:

- **Справочники и настройки** (`/settings`, руководитель): офферы, подходы, AI-сервисы с ценой кредита, ставки, мощность и WIP-лимиты креативщиков, пороги вердикта и выгорания. Старые офферы и AI-сервисы переносятся в справочники автоматически.
- **Креативы и Библиотека** (`/library`): каждый файл или ссылка из сдачи становится креативом с кодом `CD-<id>`. После правок появляются новые версии того же креатива. Фильтры (оффер, GEO, тип, подход, автор, байер, статус, период) сохраняются в ссылке. Страница креатива показывает версии, свойства, теги, себестоимость, «семейство» вариаций и историю.
- **Результаты тестов:** статистика вносится по дням в карточке креатива или загружается CSV-импортом (см. ниже). Первые данные переводят креатив в «В тесте». Система **предлагает** вердикт по порогам ROI и расхода, но ставит его всегда человек.
- **«Сделать вариации»** у победителя, среднего или выгоревшего креатива: форма ТЗ уже заполнена результатами оригинала, у новой задачи `iteration + 1`, а её креативы наследуют родителя.
- **«Моя очередь»** (`/queue`) — стартовая страница для всех ролей. Креативщик видит правки, задачи в работе, задачи, которые можно взять (с учётом WIP-лимита), и свои показатели. Байер — работы на проверку, выгорающие креативы, креативы без результатов и без вердикта. Руководитель — просрочки, задачи без исполнителя, зависшие проверки, перегруз и простой, KPI недели.
- **Шаблоны ТЗ и качество ТЗ:** шаблоны бывают личные и общие, можно скопировать прошлое ТЗ или дублировать задачу. При заполнении ТЗ показывается чек-лист из 8 правил с оценкой 0–100. Функция оценки одна на сервер и клиент: `shared/brief.js`.
- **Себестоимость:** часы из сдачи × ставка + AI-кредиты × цена. Креативщику денежные поля не отдаются.

### Формат CSV для импорта результатов

Разделитель `,` или `;` (определяется по первой строке), UTF-8 с BOM или без, первая строка — заголовки, регистр не важен:

| Колонка | Синонимы | Значение |
|---|---|---|
| `creative` | `креатив`, `code`, `код`, `объявление`, `название`, `ad`, `ad name`, `ad_name`, `creative name`, `sub_id`, `subid` | `CD-142`, `142` или название объявления с кодом внутри: `BR_nutra_CD-142_v2` |
| `date` | `дата` | `YYYY-MM-DD` или `DD.MM.YYYY` |
| `impressions`, `clicks`, `conversions` | `показы`, `клики`, `конверсии`/`leads` | целые |
| `spend`, `revenue` | `расход`/`cost`, `доход` | числа, допускается запятая |

Строки одного креатива за одну дату суммируются. Повторный импорт обновляет данные, а не дублирует. Сначала показывается предпросмотр с ошибками по строкам, ошибочные строки пропускаются. Шаблон: `GET /api/metrics/template.csv` или кнопка в окне импорта.

## Стек

- **Backend:** Node.js 20, Express, SQLite (`better-sqlite3`, режим WAL), `multer` для загрузки файлов, `bcryptjs`. Сессии хранятся в httpOnly-cookie (поддерживается и `Authorization: Bearer`).
- **Frontend:** React 18, Vite, React Router, lucide-react. Стили написаны вручную на CSS custom properties, графики — на HTML/CSS без библиотек.
- **БД:** `users`, `sessions`, `tasks`, `submissions`, `files`, `ai_expenses`, `comments`, `history`. Схема создаётся при старте ([server/db.js](server/db.js)).

```
server/
  index.js        REST API, права доступа, переходы статусов
  domain.js       матрица разрешённых действий, расчёт длительностей, просрочки
  analytics.js    агрегаты для руководителя
  seed.js         демо-данные (8 пользователей, 46 задач с историей)
  smoke-test.js   сквозной тест API (24 проверки)
client/src/
  pages/          Board, Analytics, Activity, Login
  components/     TaskModal, TaskForm, ui
```

Бизнес-правила переходов собраны в одной функции `allowedActions()` в [server/domain.js](server/domain.js). Её используют и сервер (проверка), и клиент (какие кнопки показывать). Каждый переход статуса и запись в историю выполняются в одной транзакции.

## Запуск локально

```bash
npm install
npm run build        # собрать фронтенд
npm start            # http://localhost:3001 — при первом запуске создаются демо-данные
```

Режим разработки: `npm run dev:server` и `npm run dev:client` (Vite на :5173 проксирует `/api`).
Пересоздать демо-данные: `npm run seed`. Тесты: `npm test` (поднимает сервер на временной БД).

Переменные окружения: `PORT` (по умолчанию 3001), `DATA_DIR` (БД и загруженные файлы, по умолчанию `./data`), `RESEED_ON_START=1` (пересоздавать демо при каждом старте).

## Деплой

### Render.com

Репозиторий: https://github.com/Takaesi/Creative-Desk

**Вариант 1 — Blueprint** (настройки берутся из [render.yaml](render.yaml)):
1. На [dashboard.render.com](https://dashboard.render.com) выбрать **New → Blueprint**.
2. Подключить GitHub и выбрать репозиторий `Takaesi/Creative-Desk`.
3. Нажать **Apply** и дождаться сборки (2–4 минуты). Сервис получит адрес вида `https://creative-desk-xxxx.onrender.com`.

**Вариант 2 — вручную:** New → Web Service → репозиторий, затем:

| Поле | Значение |
|---|---|
| Runtime | Node |
| Build Command | `npm install && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| Environment | `NODE_VERSION=20`, `RESEED_ON_START=1` |

Особенности бесплатного плана:
- Диск эфемерный, а сервис засыпает после 15 минут простоя. Поэтому включён `RESEED_ON_START=1`: при каждом старте создаются свежие демо-данные с актуальными датами, а изменения из прошлой сессии не сохраняются. Первое открытие после сна занимает около 30–50 секунд.
- Чтобы данные сохранялись, нужен платный план с Persistent Disk: подключить диск к `/var/data`, задать `DATA_DIR=/var/data` и убрать `RESEED_ON_START`.

### Другие варианты

- **Docker:** `docker build -t creative-desk . && docker run -p 3001:3001 -v cdesk:/app/data creative-desk`.
- Подойдёт любой хостинг с Node 20 и постоянным диском: Railway, Fly.io, VPS.

## Использованные AI-инструменты

- **Claude Code** (модель Claude Opus 5.5, расширение для VS Code) — основной инструмент. Он проанализировал задание, спроектировал архитектуру и схему БД, написал бэкенд, фронтенд, демо-данные и тесты, проверил результат и исправил найденные дефекты.
- **Как была организована работа:** один агент работал итерациями «план → код → проверка». Каждый слой проверялся сразу после написания. Генератор демо-данных подгонялся по реальному распределению статусов. API проверялся сквозным тестом полного цикла задачи по всем ролям, включая негативные сценарии и права доступа. Интерфейс проверялся в headless Chrome (puppeteer): скриншоты всех экранов в светлой и тёмной теме, на десктопе и мобильном, плюс сценарий кликов «взять → сдать с AI-расходами → принять». По скриншотам нашлись и были исправлены дефекты вёрстки.
- **Несколько агентов** в этом проекте не применялись: объём позволял держать весь контекст в одной сессии. Разумное разделение для командной работы: агент-архитектор (схема БД и контракт API), агенты бэкенда и фронтенда параллельно в отдельных git worktree, агент-ревьюер и QA-агент со smoke-тестами и скриншотами. Слияние идёт через PR.
